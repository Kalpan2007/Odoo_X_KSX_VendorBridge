# Code of Conduct

## Our standard

We work on VendorBridge as a professional engineering team. The goal is to keep collaboration clear, respectful, and focused on the product and the code.

## Expected behavior

- Be respectful in reviews, comments, and task handoffs.
- Critique the code or the design, not the person.
- Prefer clear, factual feedback over vague opinions.
- Share context when a rule, constraint, or decision matters.
- Keep workflow integrity and data safety as first-class concerns.

## Unacceptable behavior

- Harassment, discrimination, or intimidation.
- Deliberately obscuring technical decisions.
- Ignoring project rules after they have been documented.
- Introducing changes that bypass critical workflow checks without discussion.
- Misrepresenting test status, validation status, or implementation readiness.

## Review culture

- Make feedback specific and actionable.
- When rejecting a change, explain what is broken and what would satisfy the requirement.
- Prefer small, reviewable changes over large opaque rewrites.
- Treat auditability and correctness as more important than speed when they conflict.

## Conflict handling

If a disagreement cannot be resolved quickly:

1. Restate the requirement or risk.
2. Compare the candidate solutions against the documented workflow rules.
3. Choose the option that best preserves correctness, security, and maintainability.

## Scope of this document

This code of conduct applies to all contributors, maintainers, and automation agents working in the repository.
